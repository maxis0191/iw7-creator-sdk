BO3 is an optional interoperability use case, never the destination or a
mandatory prerequisite. Read [the engine strategy](docs/ENGINE-MODDING-STRATEGY.md).
Kino/Ray Gun remain particular requested demos; do not block independent useful
IW7 work behind them. Rhino stays retired and the HUD showcase stays cancelled.

second orchestrator or routine approval gate. Preserve specific execution stops.

Author manifests, validation, GSC compiler audit adapters, author examples, composition and packaging. Native engine and asset conversion implementations are versioned dependencies.

Before editing, classify the change by product and inspect `product.json`,
README.md and the migration map. This repository is the canonical owner only
for its declared exports. Do not add server logic, another product's full tree,
game assets, binaries, symbols, credentials, player data or decompiled dumps.
Extend an explicit interface/dependency rather than copying implementations.
Keep author/license notices and exact upstream pins. Never force-push history.

Preserve unrelated work, ignored evidence and frozen plans. Historical results
do not qualify relocated input identities. The owner's explicit GO on 2026-10-13
resumes work through the new orchestration. Each worker owns its assigned
canonical component; this migration does not implement other workers' features.
Preserve Main UDP27016, bank data and occupied clients. Runtime mutations still
require the applicable identity, backup and ownership checks.
Keep telemetry, shared resource leases and serialization of heavy work. The owner
lifted the older fixed disk budgets and numeric RAM/commit/headroom gates on
2026-10-13; the dedicated resource-policy worker owns their implementation.
Do not edit the scheduler here or delete its lease. Never archive a live worktree.

Use coherent codex/* commits, owner-private PRs, exact-head checks and merge
commits. Inspect actual CI jobs. Only the existing account quota refusal before
any runner/step has the owner's conditional exception; executed failures must
be fixed. Do not change visibility, billing, protection or credentials.
Return clean synchronized main; report source/build/runtime/owner validation
separately. No upstream PRs or automatic Codex memory changes.
